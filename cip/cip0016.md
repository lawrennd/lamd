# CIP-0016: Diagram source attribution from sidecar metadata

## Summary

Third-party images in `slides/diagrams/` already carry a sibling `.url` file, but the build never reads it and a URL is not a credit line. This CIP makes attribution an explicit, sidecar-driven part of the media pipeline:

1. **Canonical sidecar** — YAML next to the image (`stem.credit.yml`) storing TASL fields (Title, Author, Source, License) plus status and modifications.
2. **Explicit macro** — `\diagramcredit{stem}` looks up that sidecar at preprocess time and emits a format-specific credit. Includes do not auto-credit.
3. **Context-aware rendering** — notes/HTML get a full TASL line; Reveal slides get a compact visible credit (figure captions currently go to speaker notes only).
4. **Backfill** — Commons API for Wikimedia URLs; `.url` remains a legacy `source` shorthand.

No existing requirement covers this outcome. It is informed by *academic rigor through tooling*, *explicit over implicit*, and *configuration lives with content*. Tracked from [2026-10-25_diagram-source-attribution](../backlog/features/2026-10-25_diagram-source-attribution.md).

## Motivation

Authors reuse portraits, paintings, photographs, and diagrams from Wikimedia Commons, Flickr, Pixabay, news sites, and elsewhere. Provenance is already stored as a one-line `.url` sidecar (281 files as of 2026-10-25; ~130 Wikimedia). That information never reaches notes or slides.

Today the only working pattern is a hand-written caption, for example the Bernoulli portrait snippet. Lamd already defines `\credit{name}{url}` for slides and notes, but snippets never call it, HTML pages do not override it, and two arguments cannot carry a CC-BY credit.

A source URL is not enough for Creative Commons BY / BY-SA. Commons expects TASL. Direct `upload.wikimedia.org` links are the binary, not the File page that should be cited. Wikipedia-en uploads, news photos, and logos need a different treatment from CC works: they must not be labelled as Creative Commons.

Aligns with:

- **academic-rigor-through-tooling** — make proper attribution the easy path, without forcing one citation style on own diagrams.
- **explicit-over-implicit** — authors opt in with `\diagramcredit`; `\includejpg` does not silently grow a caption.
- **configuration-lives-with-content** — metadata lives beside the image, not in a global credits catalogue.
- **single-source-multiple-contexts** — one sidecar, different rendering for slides vs notes.
- **compose-don't-monolith** — a credit helper plus existing includes, not a new all-in-one figure macro.

### Sidecar schema

Canonical file: **`{stem}.credit.yml`** next to `{stem}.{jpg,png,svg,…}`.

```yaml
status: third-party   # own | third-party | public-domain | unknown | fair-use | trademark
title: "Portrait of Daniel Bernoulli"
author: "Johann Rudolf Huber (attrib.)"
author_url: null
source: https://commons.wikimedia.org/wiki/File:Daniel_Bernoulli.jpg
source_binary: https://upload.wikimedia.org/wikipedia/commons/…  # optional; today's .url
license: CC-BY-SA-4.0   # SPDX-like: CC-BY-4.0, CC-BY-SA-4.0, CC0-1.0, PD, Pixabay, FairUse, Unknown, Trademark
license_url: https://creativecommons.org/licenses/by-sa/4.0/
modifications: []       # e.g. ["cropped"]
```

**Resolver order** for stem `physics/daniel-bernoulli`:

1. `{diagramsdir}/physics/daniel-bernoulli.credit.yml` if present.
2. Else `{diagramsdir}/physics/daniel-bernoulli.url` as `{source: <url>, status: unknown}` — emit a source link, **do not** claim a CC license.
3. Else empty output (v1 does not fail the build).

`status: own` emits nothing unless `show_own: true` is set in the sidecar. Matplotlib SVGs and original drawings stay quiet by default.

Do not invent a CC license for `fair-use`, `trademark`, or `unknown`. Those render as “Source: …” or, for trademark/logos, nothing.

### Why YAML, not richer `.url` or Markdown fragments

| Approach | Verdict |
|---|---|
| Keep one-line `.url` and format from the URL only | Rejected: a URL is not TASL |
| Replace `.url` with YAML in place (same extension) | Rejected: extension would lie |
| Sibling `.credit.md` included by gpp | Workable, but not API-backfillable without a generator, and duplicates structured fields |
| One `_credits.yml` catalogue | Rejected: drifts from files; violates configuration-lives-with-content |
| **Sibling `.credit.yml` + legacy `.url` shorthand** | **Chosen** |

`.url` files are not deleted in v1. A backfill script writes YAML and may copy the old URL into `source_binary`.

### Author-facing macro

gpp cannot parse YAML. Expansion happens in **mdpp**, which already knows the filesystem `diagramsdir` (CIP-0010).

```markdown
\figure{\includejpg{\diagramsDir/physics/daniel-bernoulli}{35%}}{Daniel Bernoulli (1700--1782). Pressure from a gas is given by velocity of gas acting on sides.}{daniel-bernoulli}
\diagramcredit{\diagramsDir/physics/daniel-bernoulli}
```

Rules:

- `\includejpg` / `\includediagram` / `\includeimg` stay image-only.
- `\diagramcredit{stem}` is the opt-in. Stem matches the include path (no extension).
- Caption stays pedagogical; credit stays legal. Mixing them in `\figure`'s caption is still allowed, but is not the supported path.
- Missing sidecar → empty string in v1; optional later warning via `dependencies` or `--warn-missing-credits`.
- `\credit{name}{url}` remains as a manual two-argument primitive. Do not change its arity (unused today, but a silent break is unnecessary). `\diagramcredit` is the TASL path.

Sugar such as `\includejpgcredited{stem}{width}{class}` is **out of scope for v1**.

### Rendering by context

`\diagramcredit` should expand to HTML/Markdown/TeX **after** the stem is resolved, using the active `NOTES` / `SLIDES` / `TEX` flags already known to mdpp.

| Context | What the reader sees |
|---|---|
| HTML notes / ipynb notes | Full TASL: *Title* by *Author*. Source. License (linked). Modifications if any. |
| Reveal HTML slides | Compact, slide-visible, small, right-aligned: *Title* (Author, License) linking to `source`. **Not** speaker-notes-only — captions already live there. |
| TeX notes | A small credit line after the figure (Markdown links converted to `\href`). |
| PPTX / DOCX / Manim / SVG-manim | No-op in v1 (document). Manual `\credit` still works where those macros define it. |
| `null` / code extraction | Empty (existing `\credit` no-op). |

Example compact slide line:

> Portrait of Daniel Bernoulli (Huber, CC BY-SA 4.0)

Example notes line:

> *Credit:* Portrait of Daniel Bernoulli by Johann Rudolf Huber (attrib.). [Source](https://commons.wikimedia.org/wiki/File:…). [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

License labels in output use the human form (“CC BY-SA 4.0”), not the sidecar id.

### Backfill

A lamd helper (script, not a required build step) given a diagrams directory:

1. Finds `*.url` and Wikimedia `source` / `source_binary` fields.
2. Queries the Commons API (`imageinfo` + `extmetadata`) for title, artist, license, license URL, and File page.
3. Writes `{stem}.credit.yml` with `status: third-party` or `public-domain` as appropriate.
4. Leaves non-Wikimedia `.url` files alone (manual).
5. Never writes `license: CC-BY-*` for `upload.wikimedia.org/wikipedia/en/` paths; mark `fair-use` or `unknown`.

The helper is idempotent: it does not overwrite a YAML file that already has `title` and `license` unless `--force`.

### Optional later check

`dependencies` already lists included diagrams. A follow-on can warn when a third-party sidecar exists but the talk never called `\diagramcredit`, or the reverse. Not v1.

### Alternatives considered

1. **Auto-inject credit inside `\includejpg`.** Convenient, and wrong when the same file is a logo, a decorative background, or an own plot. Breaks *explicit over implicit*. Rejected for v1.
2. **Fourth argument on `\figure`.** Couples legal credit to the figure constructor; animation frames and column layouts would still need a side channel. Rejected.
3. **mdpeople-style generated `talk-credits.gpp`.** Would scan the whole diagrams tree at macro-generation time. Heavy, and CIP-0010 already gives mdpp the filesystem root needed for per-use lookup. Rejected for v1.
4. **Collected credits slide only.** Legal CC-BY practice allows a single credits list in some contexts, but notes and web pages should credit next to the work. Compact on-slide credit plus full notes line is the default; a collected slide can be added later.

### Risks

- Slide density: a credit line costs vertical space. Keep it one line, small, right-aligned.
- Wrong license from API backfill: always prefer File-page metadata; never infer CC from a bare upload URL.
- Path resolution: `\diagramcredit{\diagramsDir/…}` must use the same filesystem resolver as includes (CIP-0010). Web `diagramsurl` is not where YAML lives.
- Three-repo split: YAML lives in `slides`; macros and mdpp in `lamd`; call sites in `snippets`. Document the contract in lamd docs; do not duplicate schema.

## Implementation Plan

1. **Schema and resolver (lamd)**
   - Document the YAML fields in `docs/contexts/media.md`.
   - Python helper: given `diagramsdir` + stem, return a credit dict from `.credit.yml` or `.url`.

2. **`\diagramcredit` expansion (mdpp)**
   - Substitute `\diagramcredit{…}` using the filesystem diagrams dir.
   - Formatters for HTML notes, HTML slides, and TeX notes; empty otherwise.
   - Leave `\credit{name}{url}` unchanged.

3. **Tests**
   - Resolver: YAML wins over `.url`; `.url` alone does not claim a license; missing file → empty.
   - Expansion: notes vs slides strings; `status: own` silent; `fair-use` has no CC label.
   - Path: `\diagramsDir` prefix resolved like includes.

4. **Backfill helper**
   - Commons API client; dry-run; no overwrite of complete YAML.
   - Run against `slides/diagrams` is content work in the slides repo, not a lamd default.

5. **Docs and one snippet**
   - Media context: `\diagramcredit` and sidecar example.
   - Convert Bernoulli (already caption-credited) to sidecar + `\diagramcredit` as the reference include.

## Backward Compatibility

- Existing includes and captions keep working.
- `.url` files keep working as source-only shorthand.
- `\credit{name}{url}` arity unchanged.
- No build failure on missing sidecar.
- PPTX/DOCX/Manim output unchanged in v1.
- Authors who already put TASL in the caption may duplicate credit until they drop the caption clause; that is an opt-in content edit, not a silent change.

## Testing Strategy

- Unit tests for the resolver and for each formatter (notes HTML, slides HTML, TeX).
- Fixture directory with: full YAML, `.url` only, empty `.url`, `status: own`, `fair-use`, missing sidecar.
- mdpp integration: a tiny markdown file with `\diagramcredit{\diagramsDir/fixture}` for `--to html` with and without `SLIDES`.
- Backfill helper: mocked Commons payload → expected YAML; refuse `wikipedia/en/` as CC.
- No live Commons calls in CI.
