# CIP-0018: mdlist loads lists through lynguine, not referia

## Implementation Branch

Work will be carried out on **`cip0018-mdlist-lynguine`**, branched from `main` after this CIP is accepted.

## Summary

`mdlist` currently imports `referia.assess.data.CustomDataFrame` solely to call `from_flow`. That class is a thin subclass of lynguine's `CustomDataFrame`. The functions named in `cvlists.yml` (`convert_datetime`, `recent`, `current`, …) already live in `lynguine.util.dataframe`. Referia is the wrong dependency: it pulls Jupyter, spaCy, and Thinc into every `pip install lamd`, and the pin to an old referia rev made CV CI uninstallable once lynguine required NumPy 2.

This CIP drops referia from lamd. `mdlist` will load data with `lynguine.assess.data.CustomDataFrame.from_flow` and apply the named dataframe helpers (and the CIP-0015 pandas filters) without going through referia's Compute registry.

CIP-0015's leftover "fix referia preprocess" item is superseded. Referia remains the review tool; it is not the list-generation stack.

**Which requirements does this CIP address?** REQ-0002 (do not hide load failures behind a TypeError skip) and REQ-0005 (do not pay a spaCy/Jupyter install for eleven `mdlist` calls).

## Motivation

CV CI installs `lamd` from git `main`. That install failed on 2026-10-28 because lamd pins referia to `000328a` (`numpy<2`) while lynguine `main` requires `numpy>=2`. Referia `main` already allows NumPy 2. Bumping the pin would restore the install and still drag a review-and-NLP stack into a markdown list generator.

`mdlist` is a lamd command. The data path it needs is lynguine. CIP-0015 already moved year and current/former filters into pandas inside `mdlist` so CVs would not wait on referia's heatmap branch. Continuing to import referia for `from_flow` is the leftover coupling that made the NumPy conflict a CV blocker.

Aligns with:

- **compose-dont-monolith** — `mdlist` should compose lynguine load and lynguine dataframe helpers, not a referia review session.
- **explicit-over-implicit** — show the load and filter path in `mdlist`; do not hide it behind a subclass whose `preprocess()` does not pass `interface`.
- **academic-rigor-through-tooling** — generated lists should still honour `cvlists.yml`; the HOW should not require a second package whose compute registry mdlist does not successfully call.

## Detailed Description

### What mdlist uses today

`lamd/mdlist.py` does three referia-adjacent things:

1. `from referia import assess`
2. `data = assess.data.CustomDataFrame.from_flow(interface)`
3. `data.preprocess()` inside `except TypeError`, then `data.to_pandas()`

CIP-0015 already owns filters, sort, and integer-year coercion after that. Nothing else in lamd imports referia.

Referia's `CustomDataFrame.from_flow` calls `super().from_flow` and then `_augment_column_names`. Lynguine `from_flow` already calls `_augment_column_names` per data key (around line 1286 of `lynguine/assess/data.py`). The override is not adding a load capability mdlist needs.

Referia's `preprocess()` calls `self.compute.preprocess(data=self)` without `interface`. Lynguine `Compute.preprocess` requires `interface`. That is the TypeError CIP-0015 already skips.

### Where the cvlists.yml functions live

| Piece | Location |
|---|---|
| Load YAML / posts / glob lists | `lynguine.assess.data.CustomDataFrame.from_flow` |
| `to_pandas()` | lynguine |
| `convert_datetime`, `convert_year_iso`, `convert_int`, `addmonth`, `addyear`, `augmentmonth`, `augmentyear`, `augmentcurrency`, `current`, `former`, `recent`, `columnis`, `columncontains`, `onbool`, `descending` | `lynguine.util.dataframe` |
| Name-to-function registry used by Compute | **referia** `Compute._compute_functions_list` |
| Lynguine Compute registry | `render_liquid`, `today`, document-segment helpers only |

The functions mdlist's config names are lynguine functions. Referia Compute is a registry plus review-specific NLP/LLM ops. `mdlist` never needs the latter.

`lamd.util` already duplicates several of those dataframe helpers. This CIP does not add a third copy. After `from_flow`, call `lynguine.util.dataframe` (or the existing `lamd.util` wrappers if they stay in lockstep) from `mdlist` for preprocessor and augmentor entries that `cvlists.yml` actually names. Keep the CIP-0015 pandas filter path; do not go back to referia `filter()`.

### Chosen HOW (lamd-only first)

1. Replace the referia import with `from lynguine.assess.data import CustomDataFrame`.
2. Drop `referia = { git = ... }` from `pyproject.toml`. Keep `lynguine` on `branch = "main"`.
3. After `from_flow`, apply preprocessor and augmentor specs from the list interface by calling the lynguine dataframe functions. If a named function is missing, fail clearly (REQ-0002). Do not swallow `TypeError` from `preprocess()`.
4. Leave CIP-0015 pandas filters and sort in place.
5. Point unit tests at `lynguine.assess.data.CustomDataFrame.from_flow`, not `referia.assess.data.CustomDataFrame.from_flow`.
6. Once this is on lamd `main`, restore the CV repo workflow to `pip install git+https://github.com/lawrennd/lamd.git@main` (cv repo follow-up, not this branch).

### Follow-up (not this CIP)

Moving the dataframe function table from referia Compute into lynguine Compute would let any consumer call `compute.preprocess(data, interface)` without a private registry. That is a lynguine CIP. It is not required to drop referia from lamd. Do not block CV installs on it.

`addsupervisor` in referia's registry is a `fillna` hack. If student lists still need a supervisor default, do that explicitly in `mdlist` or in the people data, not by keeping referia for one alias.

### Alternatives considered

- **Pin referia to `main`.** Restores `pip install` because referia `main` has `numpy>=2`. Leaves Jupyter/spaCy on the lamd install path and keeps the broken `preprocess()` call. Rejected as the primary HOW.
- **Move `mdlist` into lynguine.** `mdlist` is a document generator (templates, makefile, CV list types). Lynguine is the data layer. Keep the command in lamd; consume lynguine.
- **Finish CIP-0015 Option B (fix referia preprocess).** Correct for referia reviewers. Wrong owner for CV list generation.

## Implementation Plan

1. **Swap the load path**
   - `from lynguine.assess.data import CustomDataFrame`
   - `CustomDataFrame.from_flow(interface)`
   - Remove `data.preprocess()` try/except.

2. **Apply named dataframe ops in mdlist**
   - Read `compute.preprocessor` and `compute.augmentor` from the list interface (unwrap list-vs-dict the same way CIP-0015 unwraps `compute`).
   - Dispatch to `lynguine.util.dataframe` by function name.
   - Error on unknown names.

3. **Drop the dependency**
   - Remove referia from `pyproject.toml`.
   - Drop the comment that lynguine must match referia's git ref.

4. **Tests**
   - Retarget patches in `tests/unit/test_mdlist.py`.
   - Fixture: `from_flow` plus one preprocessor (`convert_datetime` or integer year) and a `recent` filter, without referia installed.

5. **Downstream**
   - After merge to lamd `main`, restore CV CI's lamd install (separate cv commit).

## Backward Compatibility

- Generated list *content* should match CIP-0015 behaviour, plus any preprocessor/augmentor fields that were previously skipped (`month`, `year` from `addyear`, `amountstr`, and so on). CVs that include those lists may gain fields the templates already expect.
- Anyone who installed lamd and imported `referia` only because lamd pulled it in will need to depend on referia themselves. Lamd never documented that re-export.
- `pip install lamd` will no longer install spaCy models. That is intended.

## Testing Strategy

- Existing `tests/unit/test_mdlist.py` filter and template tests, with the `from_flow` mock moved to lynguine.
- A test that `pyproject.toml` does not name referia.
- Optional: `pip install .` in CI without a referia extra, then `python -c "from lamd.mdlist import main"`.
