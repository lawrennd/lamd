## Summary

Technical talks often need denser typography (equations, multi-line derivations, code) than narrative talks. Today authors either overcrowd a default-size slide, abuse `.scrollable`, or hand-edit CSS. Lamd already has clear precedents for **deck-wide** presentation chrome (`talktheme`, `talkcss`) and **per-slide** attributes (`\newslide{…}{.scrollable}`, `data-background*`). This CIP adds the same two layers for font size:

1. **Deck-wide** — frontmatter `talkfontsize` (parallel to `talktheme`).
2. **Per-slide** — named classes on `\newslide` / `\section` / `\subsection` attrs (parallel to `.scrollable`).

A small, named size scale (five steps) is defined in CSS custom properties so further sizes can be added without new macros.

**Primary format:** Reveal HTML slides. Notes / notebooks ignore size classes. PPTX / PDF are out of scope for v1 (document as no-op), matching CIP-0012 Track B.

## Motivation

Reveal’s default base size (~40px on `.reveal`) suits sparse bullet slides. Dense technical content needs a smaller base for the whole deck, plus occasional one-off slides that are smaller or larger than that deck default. Workarounds today:

- Pointing `talkcss` at a one-off stylesheet (works, but undocumented and not reusable).
- Overusing `.scrollable` (scroll during a talk is a poor substitute for readable density).
- Hard-coding `<style>` or inline `font-size` in snippets (breaks theme consistency and snippet reuse).

Aligns with:

- **configuration-lives-with-content** — size choice lives in frontmatter / slide attrs with the talk.
- **explicit-over-implicit** — named tokens (`small`, `.font-sm`), not magic auto-fit.
- **compose-dont-monolith** — CSS scale + existing attrs channel; no new slide-creation syntax required.
- **single-source-multiple-contexts** — size is a slides concern; other contexts remain unchanged.

## Detailed Description

### Existing patterns to mirror

| Concern | Deck-wide (frontmatter) | Per-slide (heading attrs) |
|---------|-------------------------|---------------------------|
| Colour theme | `talktheme: black` / `white` → pandoc `--variable theme=` | — |
| Stylesheet | `talkcss: URL` → pandoc `--css` (default `talks.css`) | `.scrollable` |
| Backgrounds (CIP-0012) | `slide_setup: …` | `data-background*` |
| **Font size (this CIP)** | `talkfontsize: medium` / `small` / … | `.font-sm`, `.font-xs`, … |

`flags.py` already reads `talktheme` and `talkcss` for the `reveal` output mode. Font size plugs into the same path.

### Size scale (five named steps)

Tokens are absolute steps relative to Reveal’s default base (`--lamd-fs-base`, default `40px`). Deck frontmatter sets the **deck scale**; per-slide classes set the **slide step relative to the current deck base** (so “this slide a bit smaller than the rest of this talk” is natural).

| Token (short) | Frontmatter aliases | Scale vs deck base | Typical use |
|---------------|---------------------|--------------------|-------------|
| `xs` | `smaller`, `x-small` | 0.70 | Very dense equation / code dump |
| `sm` | `small` | 0.85 | Technical lecture default candidate |
| `md` | `medium`, `normal` *(default)* | 1.00 | Current Reveal / narrative talks |
| `lg` | `large` | 1.15 | Title / sparse emphasis slides |
| `xl` | `larger`, `x-large` | 1.30 | Key-message / quote slides |

**Extensibility:** scales live in CSS custom properties on `:root`. Adding `xxs` / `xxl` later is a CSS-only change plus documenting the new token; macros and frontmatter accept any registered token name.

```css
:root {
  --lamd-fs-base: 40px;
  --lamd-fs-scale: 1;           /* set from talkfontsize */
  --lamd-fs-xs: 0.70;
  --lamd-fs-sm: 0.85;
  --lamd-fs-md: 1.00;
  --lamd-fs-lg: 1.15;
  --lamd-fs-xl: 1.30;
}
.reveal {
  font-size: calc(var(--lamd-fs-base) * var(--lamd-fs-scale));
}
.reveal .slides section.font-xs { font-size: calc(1em * var(--lamd-fs-xs)); }
.reveal .slides section.font-sm { font-size: calc(1em * var(--lamd-fs-sm)); }
.reveal .slides section.font-md { font-size: calc(1em * var(--lamd-fs-md)); }
.reveal .slides section.font-lg { font-size: calc(1em * var(--lamd-fs-lg)); }
.reveal .slides section.font-xl { font-size: calc(1em * var(--lamd-fs-xl)); }
```

Headings in `talks.css` already use `em` relative to `.reveal` / section, so they shrink/grow with the scale. Code blocks and MathJax inherit the section size; authors who need maths *larger* than body text keep using existing display-math conventions.

### 1) Deck-wide: `talkfontsize` frontmatter

```yaml
---
title: "Variational Inference"
talktheme: white          # existing
talkfontsize: small       # new — deck base = 0.85 × Reveal default
---
```

Behaviour:

- Default when unset: `medium` (no visual change vs today).
- `flags.py` (`output == "reveal"`) resolves the token and emits:
  - an extra `--css` pointing at a **lamd-shipped** stylesheet `slide-fonts.css` (always included for reveal, or included whenever `talkfontsize` is set / always for predictability), and
  - a tiny header snippet or CSS variable injection setting `--lamd-fs-scale` (e.g. `--include-in-header` `<style>:root{--lamd-fs-scale:0.85}</style>`, or a pandoc variable consumed by the reveal template).
- Invalid tokens → clear error from `flags` / build (explicit-over-implicit), listing allowed names.

**Where the CSS lives:** ship `lamd/includes/slide-fonts.css` (or `lamd/assets/css/…`) inside the package so builds do not depend on updating the external default `talks.css` on inverseprobability.com / jekyll-theme. Optionally later merge rules into jekyll-theme `talks.css` for site-hosted decks; package CSS remains the source of truth for `maketalk`.

**Interaction with custom `talkcss`:** both stylesheets apply (pandoc `--css` can be repeated). Custom CSS can override `--lamd-fs-*` variables. Document that custom sheets should prefer variables over hard-coded `.reveal { font-size: … }` so deck tokens keep working.

### 2) Per-slide: classes on existing heading attrs

No new required macro arity. Authors already pass attrs as the second argument:

```markdown
\newslide{ELBO derivation}{.font-sm}
\newslide{Key takeaway}{.font-lg}
\newslide{References}{.scrollable .font-sm}
\section{Appendix: full expansion}{.font-xs}
```

Pandoc reveal already maps `{.font-sm}` on `##` headings to `class="… font-sm"` on the `<section>` (same mechanism as `.scrollable`).

**Optional convenience macros** (nice-to-have, same file as other slide helpers):

```markdown
\define{\slidefont{size}}{.font-\size}
\newslide{ELBO}{\slidefont{sm}}
```

Do **not** invent `\newslidesmall{…}` / `\newslidelarge{…}` as primary API — that would multiply slide constructors and fight the attrs channel established for backgrounds and scrollable. Helpers that *emit* attrs are fine.

`\subsection` / `\subsubsection` today do not take an attrs argument. Options (choose in implementation; prefer A unless authors need subsection attrs widely):

- **A (recommended for v1):** document that size classes apply to `\newslide` and `\section` (both already accept `{commands}` / attrs). Leave subsection signatures unchanged.
- **B:** extend `\subsection{text}{commands}` to match `\newslide` / `\section` (small macro change; more consistent).

### Clash / precedence policy

| Layer | Wins when |
|-------|-----------|
| Per-slide `.font-*` | Slide has an explicit font class |
| Deck `talkfontsize` | No per-slide font class |
| Reveal / theme default | Neither set (`medium`) |

Multiple `.font-*` on one slide: last class in CSS file wins (document “use one size class per slide”). Combining `.font-sm` with `.scrollable` is supported and encouraged for long reference slides.

### Format matrix

| Output | Deck `talkfontsize` | Per-slide `.font-*` |
|--------|---------------------|---------------------|
| Reveal HTML | Yes | Yes |
| Notes HTML / PDF | No-op | No-op |
| Notebook | No-op | No-op |
| PPTX | No-op (v1) | No-op (v1) |

Rationale: PPTX font size is driven by the reference `.potx`, not Reveal CSS. A later CIP could map tokens to potx variants if needed; do not half-implement.

### Alternatives considered

| Alternative | Why not (for v1) |
|-------------|------------------|
| Only document “set `talkcss` to a denser sheet” | Works but is not a discoverable standard; every talk reinvents scales |
| Auto-fit / shrink-to-fit JS | Implicit, fragile with MathJax and fragments; violates explicit-over-implicit |
| New `\newslidesmall` macros only | Does not cover deck-wide; proliferates constructors |
| Absolute per-slide sizes ignoring deck | Worse for “one denser slide in this talk”; absolute can be added later as `.font-abs-sm` if snippet reuse demands it |
| Change Reveal theme files | Themes are upstream CDN assets; lamd overlay CSS is the right layer |

## Backward Compatibility

- Unset `talkfontsize` → `medium` → **no visual change**.
- Existing `.scrollable` and `data-background*` unchanged.
- Existing custom `talkcss` continues to work; may override font variables intentionally.
- No requirement to edit old talks.

## Testing Strategy

- Unit: `talkfontsize` alias normalisation and pandoc flag emission (`test_flags.py`).
- Unit / snapshot: CSS file contains expected variables and class names.
- Integration (lightweight): preprocess a fixture markdown with `\newslide{…}{.font-sm}` and assert the attrs survive to the reveal intermediate / HTML section class list.
- Manual: build one technical talk at `talkfontsize: small` and spot-check MathJax, code blocks, and a `.font-lg` title slide.
