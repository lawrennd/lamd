## Summary

`mdlist` still writes some `.markdown` files, but CV lists are not usable: year and current/former filters are skipped, teaching and people templates crash, invited-talk output is empty bullets, and grant years render as 1970. This CIP restores list generation inside lamd so the private CV repo can stop hand-writing lists that already have data sources.

Reintegration of those lists into the CVs, and the data-file PRs that go with it, live in cv CIP-0006. This CIP is the lamd (and, where unavoidable, referia/lynguine) HOW.

## Motivation

Recent include-based CVs needed recent publications, talks, teaching, grants, and group lists. `mdlist` is the tool that is supposed to produce those from `publications/_posts`, `talks/_posts`, `data/*.yaml`, and a people tree. After the compile-blocker fixes, `mdlist` runs, but:

1. `data.preprocess()` is swallowed, so `-s` / `publicationsince` / current vs former never apply.
2. `listteaching.md` uses Liquid reserved word `with`.
3. `{% include 'listperson' %}` does not find `listperson.md` under the current python-liquid loader.
4. Talk discovery scans the whole talks repo, not `_posts`, and `listtalk.md` then prints empty `* , **, ` lines.
5. Integer grant years (`start: 2016`) go through Liquid's date filter as Unix timestamps and become 1970. `listgrant.md` also emits a literal `\n`.

The CV repo therefore handwritten dated engagement lists, and some teaching and researcher-development includes explicitly omit generated lists. CVs that still `\include` publication and talk lists currently ship the unfiltered or empty output.

## Detailed Description

### What was probed (2026-10-23)

Live data, lamd `.venv` `mdlist` 0.1.3:

| List | Result |
|------|--------|
| `publications` (sample and a full CV makefile) | Writes. Career list from 1998 despite `publicationsince: 2019`. |
| `grants` / `exgrants` | Writes. Byte-identical. Several rows `from 1970 to 1970`. |
| `meetings` vs `meetings -s 2020` | Writes. Identical; still includes 2018 GPSS. |
| `teaching` / `exteaching` | `LiquidSyntaxError: expected a primitive expression, found with` in `listteaching.md`. |
| `exstudents` / `expdras` | `TemplateNotFoundError: listperson`. |
| `talks` via `make invited-talk-list.markdown` | 1,324 lines of `* , **, `. |

`Compute.preprocess(self, data, interface)` requires `interface`. `referia.assess.data.CustomDataFrame.preprocess()` still calls `self.compute.preprocess(data=self)`. `mdlist.py` catches `TypeError` and continues with an all-true filter.

Newer python-liquid has no `liquid.loaders.FileExtensionLoader`. `lynguine.util.liquid.load_template_env` therefore uses `FileSystemLoader`, so `get_template("liststudent.md")` works (mdlist adds `.md`) but `{% include 'listperson' %}` looks for a file named `listperson` with no suffix.

Talk files that belong on a CV are `talks/_posts/*.md` (`title`, `venue`, `date`, `layout: talk`). `_lamd.yml` sets `talksdir` to the talks repo root, and `make-lists.mk` does `find $(TALKSDIR) -name '*.md'`, so lecture notes under `_accelerate/` and similar are included. Many of those have no `venue`/`date`; the empty bullets are the template filling missing fields, at scale.

### Design

Do the CV-visible work in lamd so we are not blocked on referia's current heatmap branch or on a lynguine loader rewrite.

**1. Templates (lamd-only, first PR).**

- `listteaching.md`: rename the collaborator field from `with` to `collaborators` (already used in `grants.yaml`). Use `{% if collaborators %}`.
- `liststudent.md` / `listpdra.md`: `{% include 'listperson.md' %}` (and the same suffix on nested includes if they fail).
- `listgrant.md`: drop the literal `\n`; keep a real newline if a blank line between items is wanted.
- `listtalk.md`: keep `title` / `venue` / `date`; skip rows that have no title (defence in depth once the glob is narrowed).

**2. Filtering in mdlist (lamd, Option D from `2025-12-02_mdlist-preprocess-filtering`).**

Do not wait for referia. After `from_flow`, apply pandas filters in `mdlist.py` from CLI `-s` and from `cvlists.yml` filter names we actually use:

- `recent` / since-year: `year >= SINCE_YEAR` (derive year from `year`, else `date`/`published`/`start`).
- `current` / `former`: compare `end` (and `current` bool if present) to today.
- `columnis` / `columncontains` / `onbool`: the student and PDRA selectors.

Stop swallowing `TypeError` from `preprocess()`. Call it if it succeeds; if it still raises, log once and run the pandas path. Sorting: `sort_values` on the `sorter.by` fields when present.

This is explicit over implicit: the CV makefile already passes `-s ${PUBLICATIONSINCE}`. The filter must honour that argument even if lynguine compute stays broken.

**3. Talk source glob (lamd makefile + documented `_lamd.yml` convention).**

`make-lists.mk` should list `$(TALKSDIR)/_posts` when that directory exists, otherwise `$(TALKSDIR)`. A CV `_lamd.yml` can also set `talksdir` to that `_posts` directory. Either change is enough; do both so a default talks checkout still works.

**4. referia follow-up (separate PR, not a CV blocker).**

`CustomDataFrame.preprocess()` should pass `interface=self.interface` (or the compute interface) into `Compute.preprocess`. That restores `convert_datetime`, `convert_year_iso`, augmentors. Until then, data-side ISO dates (cv CIP-0006 / data PR) make Liquid `date: "%Y"` safe.

**5. Out of scope here.**

- A new `mdlist` type for Judge / LUISS / corporate speaking. Those stay handwritten dated includes until a later CIP (talks already has `_execed/`).
- mdlist server mode (CIP-0008 Phase 3).
- PDF via cvneil.

### Alternatives considered

- **Fix only in referia (Option B).** Correct long-term, but referia is on `cip001A-heatmap-chapter-alignment` and CVs need lists now.
- **Rename Liquid `with` in data only.** The template still cannot parse `{% if with %}`. The YAML key must change with the template.
- **Keep handwritten lists.** Fine for engagement diaries with no mdlist type. Wrong for publications, talks, grants, teaching, and the group: those already have sources, and some CVs already include the generated files.

## Implementation Plan

1. **Templates PR (lamd)**
   - Fix `listteaching.md`, `liststudent.md`, `listpdra.md`, `listgrant.md`.
   - Tests that render each template with a fixture dict (no lynguine required).
2. **Filtering PR (lamd)**
   - Pandas since-year / current / former / column filters in `mdlist.py`.
   - Stop silent `except TypeError: pass`.
   - Tests: publications `-s 2020` drops 1998; grants vs exgrants differ; meetings `-s 2020` drops 2018.
3. **Talks glob (lamd makefile)**
   - Prefer `$(TALKSDIR)/_posts`.
   - Test or makefile comment so empty `_posts` still yields an empty list, not a scan of `.`.
4. **referia PR (follow-up)**
   - Pass `interface` into `Compute.preprocess`.
   - Tiny test on `CustomDataFrame.preprocess`.
5. **cv CIP-0006**
   - Data dates, `teaching.yaml` `collaborators`, `_lamd.yml` talks path, re-enable includes. Separate PRs; this CIP does not land CV content.

## Backward Compatibility

- YAML `with:` under teaching must become `collaborators:` in the teaching data file in the same window as the template PR, or teaching lists are empty of co-teachers rather than crashing.
- CVs that already include generated lists will change content once filters work (a `publicationsince: 2019` list will start at 2019, not 1998). That is the intended correction.
- Handwritten `executive-education-list.md` is unchanged.

## Testing Strategy

- Unit tests in `tests/unit/test_mdlist.py` for year cut, current/former split, and template render.
- Fixture trees: a few publication posts, one `_posts` talk, a grants YAML with mixed ISO and (until the data PR) integer years.
- Manual: `make publication-list.markdown invited-talk-list.markdown current-teaching-list.markdown` in a CV directory after the reintegration PR, and confirm `publicationsince` / `talksince` are honoured.
