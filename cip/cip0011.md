## Summary

**Rejected.** This CIP put the HOW in the wrong library and treated the absence of a lynguine registry as a reason not to build one.

Publish/subscribe of named flows is lynguine infrastructure: `Interface` already defines connections to other black-box processes. The replacement is [lynguine CIP-000C](https://github.com/lawrennd/lynguine/blob/main/cip/cip000C.md) (Proposed), implementing [lynguine REQ-000C](https://github.com/lawrennd/lynguine/blob/main/requirements/req000C_named-flow-composition.md). Lamd CIP-0006 generate/execute **consumes** that registry; it does not replace it with "the YAML file is the bus."

**Which requirements does this CIP address?** None, once rejected. REQ-0003 remains; its HOW for registration is lynguine CIP-000C plus CIP-0006.

## Motivation

[lamd#5](https://github.com/lawrennd/lamd/issues/5) asked to generate an interface, register it with a publish/subscribe service, then execute. CIP-0006 covers generate and execute. This document originally argued that no such service exists in lamd, lynguine, or referia, so registration should mean "write a file and let Make or a lynguine session read it."

That was the wrong conclusion. The service does not exist *as code* because it has not been built. The *capability* is the intended lynguine/Linguine matching layer: named publish and subscribe on top of `from_flow` / `to_flow`. Building that in lamd would duplicate infrastructure. Pretending files-plus-Make are enough leaves processes coupled by path convention.

## Detailed Description

The rejected HOW was:

- Writing `{basename}.interface.yml` counts as publish.
- Make, CI, git, or a lynguine session counts as subscribe.
- Do not build a registry in lamd or lynguine.

The accepted direction (in lynguine, not here):

- Outputs declare `publish.name`.
- Inputs declare `source.type: flow` (same `source` hook as lynguine CIP-0009).
- A `FlowRegistry` binds names to current locations during flow execution.
- Lamd `--execute` calls `register_interface`, then runs the documented compute.

See lynguine CIP-000C for the full design. This file is kept so the GitHub issue and CIP-0006 history still resolve.

## Implementation Plan

None. Do not implement a lamd-owned "file is the contract" registration story. Implement lynguine CIP-000C; then CIP-0006 Phase 2 registers generated interfaces with that registry.
