# CIP-0010: Unified Diagram Path Resolution

## Status

- [x] Proposed — Initial documentation complete
- [x] Accepted — Plan reviewed and approved
- [x] In Progress — Actively being implemented
- [ ] Implemented — Work complete, awaiting verification
- [ ] Closed — Verified and complete
- [ ] Rejected — Will not be implemented
- [ ] Deferred — Postponed

## Summary

Introduce a single, explicit path-resolution layer for diagram locations so that
filesystem paths (make, Inkscape, pandoc, `dependencies`) and web URLs (HTML,
ipynb) are no longer derived from the same overloaded `diagramsdir` field with
ad hoc special cases in shell scripts and makefiles.

This CIP implements the architectural fix tracked in backlog task
[2025-05-22_path-handling-consistency](../backlog/features/2025-05-22_path-handling-consistency.md)
and documents current behaviour in
[Directory paths in LaMD builds](../docs/guides/directory-paths.md).

## Motivation

LaMD builds fail in confusing ways when different tools disagree about where
diagrams live. A recent example (`basis-functions-and-generalisation.pptx` from
`mlfc/_lamd`) showed three different locations in play at once:

| Consumer | Path used |
|----------|-----------|
| pandoc / markdown | `./slides/diagrams//ml/quadratic_basis000.emf` (wrong `diagramsdir`) |
| Inkscape / make (legacy) | hardcoded user-specific tree outside the project |
| SVG sources | `../slides/diagrams/ml/` (correct for `_lamd` cwd) |

Symptoms are not limited to PPTX:

1. **`diagramsdir` is overloaded** — In `mdpp`, the same YAML value becomes a
   filesystem path for pptx/docx/tex and a URL prefix fragment for html/ipynb
   (`url + baseurl + diagramsdir`, unless `diagramsurl` overrides).
2. **Resolution is duplicated** — `mdpp`, `dependencies`, makefiles, and
   `copy_web_diagrams.sh` each implement partial logic; only some honour
   `--diagrams-dir`.
3. **`_lamd` special cases** — `copy_web_diagrams.sh` prepends `../` to
   `diagrams_dir` when cwd basename is `_lamd`, but not to `slides_dir` or
   `snippets_dir`, hiding misconfiguration instead of fixing it.
4. **Hardcoded drift** — `make-tex.mk` passes `--diagrams-dir diagrams` instead
   of `$(DIAGRAMSDIR)`, so TeX builds can disagree with every other format.
5. **Opaque concatenation** — Paths like `../slides/diagrams//ml/foo` work on
   Unix but signal missing normalisation and make debugging harder.

These issues violate the project tenet *show the path, don't hide it*: users
cannot predict where a diagram will be read or written without reading several
tools' source files.

## Detailed Description

### Design goals

1. **One resolver, many consumers** — All tools call the same functions to turn
   config + cwd + CLI overrides into concrete paths or URLs.
2. **Separate filesystem from web** — YAML and CLI distinguish “where files are
   on disk” from “what `\diagramsDir` means in published HTML”.
3. **Build cwd as the anchor** — Relative paths resolve from the directory where
   `maketalk` / `make` runs (typically `_lamd/`), documented and enforced.
4. **No directory-name magic** — Remove `_lamd`-specific branches; if paths are
   wrong, fail with a clear message pointing at config and cwd.
5. **Backward compatible migration** — Existing `_lamd.yml` files keep working;
   deprecated combinations emit warnings before removal in a later release.

### Current behaviour (baseline)

Documented in [docs/guides/directory-paths.md](../docs/guides/directory-paths.md).
Key code paths today:

- `lamd/mdpp.py` — dual `\diagramsDir` assignment (lines ~183–198)
- `lamd/dependencies.py` — `resolve_diagrams_dir()` (CLI or `diagramsdir` only)
- `lamd/makefiles/make-talk-flags.mk` — `DIAGRAMSDIR` from `mdfield batch`
- `lamd/scripts/copy_web_diagrams.sh` — `_lamd` adjustment for `diagrams_dir` only
- `lamd/makefiles/make-tex.mk` — hardcoded `diagrams` for notes TeX preprocess

Makefiles already pass `--diagrams-dir $(DIAGRAMSDIR)` for most targets; the gap
is consistency in `mdpp` defaults, TeX, web copy, and URL vs filesystem split.

### Observed configuration patterns (2026-08-09 audit)

We scanned `_lamd.yml` files under `~/mlatcl/*/_lamd/` (15 configs, excluding
`tmp/`) and `~/lawrennd/talks/*/` (17 topic configs). **No project sets
`diagramsurl`**; all web-facing `\diagramsDir` values are inferred from
`url + baseurl + diagramsdir` in `mdpp` when `--to html` or `--to ipynb`.

Build cwd is assumed to be `_lamd/` for courses and each `talks/_topic/` for
talks. The table summarises recurring combinations.

| Pattern | `diagramsdir` | `slidesdir` | `url` / `baseurl` | Repos (count) | Local PPTX risk |
|---------|---------------|-------------|-------------------|---------------|-----------------|
| **A — course template (relative mismatch)** | `./slides/diagrams/` | `../slides/` | `mlatcl.github.io` + course code | advds, dsa, deepnn, execed, gpss, iei, mlphysical, r250, r255, tig, course-template, vibecourse template (**12**) | **High** — `./` resolves under `_lamd/slides/`, not `project/slides/` |
| **B — course (consistent relative)** | `../slides/diagrams/` | `../slides/` | `mlatcl.github.io` + `mlfc/` | mlfc (**1**) | Low — matches layout in [directory-paths.md](../docs/guides/directory-paths.md) |
| **C — course + shared home slides tree** | `../slides/diagrams/` | `$HOME/lawrennd/slides/` | `mlatcl.github.io` + course code | mlai, atomichuman (**2**) | Medium — diagrams relative to `_lamd`, slide HTML copied elsewhere |
| **D — talks (uniform)** | `../slides/diagrams/` | `$HOME/lawrennd/slides/` | `inverseprobability.com` + `talks/` | all 17 topics (`_ml`, `_ai`, …) | Low for diagrams; slides output decoupled from repo |

#### Pattern A — `./slides/diagrams/` with `../slides/` (most mlatcl courses)

Typical excerpt (`advds/_lamd/_lamd.yml`, shared by iei, tig, dsa, …):

```yaml
slidesdir: ../slides/
diagramsdir: ./slides/diagrams/
url: "https://mlatcl.github.io/"
baseurl: advds/
```

From `_lamd/` cwd:

- **Filesystem (pptx, make, dependencies):** `./slides/diagrams/` →
  `_lamd/slides/diagrams/` (usually **empty or wrong**).
- **Actual SVG tree:** `../slides/diagrams/ml/` → `project/slides/diagrams/ml/`.
- **HTML `\diagramsDir` (mdpp):** concatenates to something like
  `https://mlatcl.github.io/advds/./slides/diagrams/` — may work in browsers
  after normalisation, but **does not match** the filesystem path make needs.

`copy_web_diagrams.sh` partially masks this for publish: when cwd is `_lamd`, it
prepends `../` to `diagrams_dir` only, so web copy reads
`.././slides/diagrams/` ≈ `project/slides/diagrams/`. PPTX and Inkscape do not
get that hack — which is why mlfc’s PPTX failure surfaced before HTML publish did.

#### Pattern B — `../slides/diagrams/` (mlfc, post-fix)

```yaml
slidesdir: ../slides/
diagramsdir: ../slides/diagrams/
url: "https://mlatcl.github.io/"
baseurl: mlfc/
```

Filesystem and diagram sources align. For HTML, mdpp still sets
`\diagramsDir` to `https://mlatcl.github.io/mlfc/../slides/diagrams/` unless
overridden — a separate web-path question addressed by `diagramswebpath` /
`diagramsurl` in the proposed model.

#### Pattern C — shared slides output directory (mlai, atomichuman)

```yaml
slidesdir: $HOME/lawrennd/slides/
diagramsdir: ../slides/diagrams/
scriptsdir: https://inverseprobability.com/talks/scripts/
url: "https://mlatcl.github.io/"
baseurl: mlai/   # or atomichuman/
```

Diagram sources sit in the **course repo** (`../slides/diagrams/` from `_lamd/`),
but built slide HTML is copied to a **central tree** under `$HOME/lawrennd/slides/`.
`slidesdir` and `diagramsdir` therefore answer different questions; conflating
them in mental models causes confusion. `scriptsdir` is already a full URL here
(another overloaded “path” field).

#### Pattern D — talks repo (all topics identical)

Excerpt from `talks/_ml/_lamd.yml` (same in `_ai`, `_business`, …):

```yaml
postsdir: ../_posts/
slidesdir: $HOME/lawrennd/slides/
diagramsdir: ../slides/diagrams/
scriptsdir: https://inverseprobability.com/talks/scripts/
url: https://inverseprobability.com/
baseurl: talks/
```

Talks build from `talks/_ml/` (not `_lamd/`), but the same structural split
applies: diagrams relative to the topic directory, slides published to a shared
home path, web site at `https://inverseprobability.com/talks/…`. HTML
`\diagramsDir` becomes `https://inverseprobability.com/talks/../slides/diagrams/`
under current mdpp rules — again mixing URL composition with a filesystem-relative
fragment.

#### Audit takeaways for CIP-0010

1. **Two dominant `diagramsdir` spellings** — `./slides/diagrams/` (12 mlatcl
   courses) vs `../slides/diagrams/` (mlfc, mlai, atomichuman, all talks). The
   `./` form is the main PPTX/make failure mode when cwd is `_lamd/`.
2. **`diagramsurl` unused** — every site relies on implicit
   `url + baseurl + diagramsdir`; explicit web prefixes would clarify Pattern C/D.
3. **`copy_web_diagrams.sh` hack correlates with Pattern A** — repos that need
   `../` adjustment are exactly those with `./slides/diagrams/`.
4. **Template propagation** — `course-template` and `vibecourse` templates ship
   Pattern A; fixing the template fixes future courses once resolver + docs land.
5. **Migration scope** — mechanical fix for Pattern A: change one line to
   `diagramsdir: ../slides/diagrams/` (already done for mlfc); no talks changes
   required for filesystem paths.

### Proposed configuration model

Keep existing keys but **fix semantics** and add one optional key:

| Field | Role after CIP-0010 |
|-------|---------------------|
| `diagramsdir` | **Filesystem only** — root for SVG/EMF/PDF/PNG relative to build cwd. Used by make, Inkscape, `dependencies`, pandoc resource resolution, and local `\diagramsDir` for pptx/docx/tex. |
| `diagramsurl` | **Web prefix only** — full URL prefix for `\diagramsDir` in html/ipynb (unchanged intent, documented as the primary web control). |
| `diagramswebpath` (new, optional) | URL path suffix after `url + baseurl` when diagrams are served under a subpath that is not `diagramsdir`. Example: `slides/diagrams/` on site vs `../slides/diagrams/` on disk. |

**Resolution rules:**

```text
filesystem_diagrams_dir =
  CLI --diagrams-dir
  ?? normalise(config.diagramsdir) relative to build_cwd

web_diagrams_dir =
  CLI --diagrams-web-dir (new, optional override for html/ipynb only)
  ?? config.diagramsurl
  ?? (config.url + config.baseurl + config.diagramswebpath)
  ?? (config.url + config.baseurl + basename(normalised diagramsdir))
```

For **html/ipynb**, `mdpp` sets `-DdiagramsDir=` to `web_diagrams_dir` unless
`--diagrams-dir` is passed (filesystem override for local preview builds).

For **all other `--to` values**, `mdpp` sets `-DdiagramsDir=` to
`filesystem_diagrams_dir`.

`--diagrams-dir` continues to mean “filesystem root” everywhere (makefiles
unchanged). A new optional `--diagrams-web-dir` applies only when `--to` is
html or ipynb.

### Unified resolver module

Add `lamd/paths.py` (name tentative) with:

- `get_build_cwd()` — explicit cwd (default `.`), testable
- `normalise_path(path, base)` — collapse `//`, resolve `.` and `..` where safe
- `resolve_diagrams_filesystem(config, cwd, cli=None) -> str`
- `resolve_diagrams_web(config, cli_fs=None, cli_web=None) -> str`
- `validate_diagrams_root(path) -> None` — optional helper for clear errors

**Consumers to migrate:**

| Component | Change |
|-----------|--------|
| `mdpp.py` | Call resolver; remove inline url/baseurl concatenation for local formats |
| `dependencies.py` | Delegate to `resolve_diagrams_filesystem`; share normalisation |
| `copy_web_diagrams.sh` | Remove `_lamd` branch; accept pre-resolved path from make **or** call a thin Python wrapper `lamd-resolve-diagrams-dir` that prints the filesystem path |
| `make-tex.mk` | Replace `--diagrams-dir diagrams` with `--diagrams-dir ${DIAGRAMSDIR}` |
| `make-ipynb.mk` | Pass explicit web vs filesystem flags if ipynb needs local assets on disk |

Prefer a **Python CLI entry point** (e.g. `python -m lamd.paths --filesystem`)
over duplicating logic in bash, so `copy_web_diagrams.sh` stays a thin orchestrator.

### Error messages

When a diagram file is missing, messages should state:

- expected filesystem path (absolute or cwd-relative)
- build cwd
- config key (`diagramsdir`) and CLI override if any
- which tool failed (`dependencies`, pandoc, Inkscape)

This supports [REQ-0002](../requirements/req0002_clear-error-messages.md).

### Alternatives considered

| Approach | Verdict |
|----------|---------|
| **Path type prefixes (`file:`, `url:`)** | Rejected for now — breaks every existing `_lamd.yml` without a mechanical migrator |
| **Path context objects everywhere in make** | Too heavy for makefiles; resolver in Python with make calling one command is enough |
| **Standardised base paths only** | Insufficient — does not separate web URL from filesystem |
| **Document only (no code)** | Already done in `directory-paths.md`; insufficient — special cases remain |

### Relationship to other work

- **Macro-aware diagram dependencies** (lynguine / REQ-0008) — orthogonal; ensures

- **Recent tactical fixes** — `resolve_diagrams_dir()` in `dependencies.py` and

## Backward Compatibility

- **`diagramsdir`** remains the primary key; semantics narrow to filesystem only.
  Projects that already use `../slides/diagrams/` require no change (Patterns B,
  C, D — mlfc, mlai, atomichuman, all talks).
- **Pattern A courses** (`./slides/diagrams/`) — should migrate to
  `../slides/diagrams/` regardless of resolver work; today they depend on
  `copy_web_diagrams.sh`’s `_lamd` hack for publish and break local pptx/tex.
- **HTML/ipynb** — Projects relying on `url + baseurl + diagramsdir` for
  `\diagramsDir` continue to work via the web resolver fallback chain. Projects
  with odd URL layouts should set `diagramsurl` explicitly (already supported).
- **`copy_web_diagrams.sh`** — Removing `_lamd` prepend may break configs that
  depended on the hack *instead of* correct `diagramsdir`. Mitigation: release
  note + warning when resolver path does not exist, pointing at
  `directory-paths.md` checklist.
- **CLI** — `--diagrams-dir` behaviour unchanged for make-driven builds.
